The data is relational: incidents refer to users, services, categories and each other; SLA
reporting and the audit trail need joins and integrity constraints. Eighteen tables hold it.
The same SQLAlchemy models and Alembic migrations run on SQLite in development and tests and on
PostgreSQL in Docker, CI and the cloud.

\section{Important relationships}
\begin{itemize}
  \item \textbf{User--Incident} twice: every incident has exactly one reporter and at most one
    assignee. Ownership checks (BR-01, BR-02) read these keys.
  \item \textbf{Incident--Incident:} a cancelled duplicate points at the incident it duplicates
    through \code{parent\_id}; that link is also what subscribes its reporter to the original
    (D-005).
  \item \textbf{Service--Service:} \code{service\_dependencies} forms a directed graph; the
    correlation engine walks it breadth-first to find an open P1 or P2 on a service the
    reported one depends on.
  \item \textbf{Composition:} work notes, the resolution, feedback, the embedding and SLA
    violations belong to one incident and are loaded and saved with it by the repository.
  \item \textbf{Audit:} \code{audit\_log.incident\_id} is a real foreign key, nullable because
    sign-ins and configuration changes are audited too.
\end{itemize}

\section{Integrity, performance and portability}
\begin{itemize}
  \item \textbf{Constraints} enforce what the domain also checks: unique emails and names,
    foreign keys everywhere (SQLite connections switch \code{foreign\_keys=ON}, which is off by
    default), one resolution and one feedback per incident.
  \item \textbf{Transactions:} a change and its audit records commit together through one unit
    of work; a concurrent edit fails the \code{version} check and returns 409 instead of
    silently overwriting. Appends to the audit chain lock its head row, so two writers cannot
    fork the chain.
  \item \textbf{Indexes} serve the queues and the search: status with priority, assignee with
    status, creation time, status with resolution deadline (the monitor's query), and the
    foreign keys.
  \item \textbf{Time} is stored as timezone-aware UTC and displayed in IST.
  \item \textbf{No string-built SQL:} every query goes through the ORM, which binds parameters.
  \item \textbf{Migrations:} Alembic, one linear history (a test checks there is exactly one
    head); the API image runs \code{alembic upgrade head} before it serves.
  \item \textbf{Nothing is hard-deleted:} incidents end CLOSED or CANCELLED, users are
    deactivated, services and categories retired (BR-10).
\end{itemize}
